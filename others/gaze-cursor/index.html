gaze-cursor

Webカメラの映像から視線を推定して、カーソルを目で動かす

idle

概要

画面の9点を順に注視してもらって、そのときの目と虹彩の位置から画面座標への回帰を最小二乗で解きます。 あとはそれに今の目の位置を入れて出てきた座標を、制御側が一定周期で追いかけます。

カーソルはこのページの中だけの仮想カーソルです。OS のカーソルは動かしません。 ページ内に5つの的を置いてあるので、視線で運んで注視したままにすると、そこが押されます。

推定側と制御側を分けてあります。推定側は「今どこを見ているか」を出すだけで、 カーソルをどう動かすかは決めません。移動量の制限、注視クリック、観測が途切れたときの停止は 制御側（controller.js）の仕事で、出力先は Actuator という5つだけの口を通します。 差し替えるのはこの口の実装だけで済むので、視覚の前段を変えても制御は壊れません。

使い方

  1. START を押してカメラを許可（全画面になります）
  2. CALIBRATE を押して、出てくる9点を順に目で追う
  3. START TRACKING でカーソルが視線で動きます。的を注視したままにすると押されます

止めるときは Esc か、画面下の EXIT。 Space でも追跡の入／切を切り替えられます。 うまく動かないときは PREVIEW でカメラの写りを確認して、必要なら CAMERA で別のカメラに切り替えてください。

仕組み

要素内容
視線推定 MediaPipe FaceLandmarker（478点）の虹彩ランドマークを、目頭・目尻の線分と上瞼・下瞼の線分に射影して比率化
キャリブレーション 9点それぞれで40フレームの中央値を取り、その特徴量から画面座標へのリッジ回帰を x/y 別に解く。外れ値は leave-one-out で1点まで除外
なめらか化 直近3フレームの中央値で単発のスパイクを落としてから 1€ filter に通す。止まっているときは強く平滑化し、速く動くときは遮断周波数を上げて遅れを出さない
境界 推定側は「視線の観測」を制御側に渡すだけ。移動・停止の判断は制御側が持つ
制御 推定レートとは別に 100 Hz の固定周期で回す。最新の視線と現在位置から移動量を決め、1周期の移動量に上限を入れて比例制御で収束させる
フェイルストップ 観測が 400 ms 途切れたら一時停止、2.5 s 途切れたら要再アームにする
注視クリック 視線が 900 ms 止まったら発火（カーソルの周りに進捗リングが出ます）
計測 HUD に、制御側の状態、視線サンプルから反映までの遅延、カメラの実解像度と fps、顔検出の取りこぼし率を常に出している

移植について

計算は core.js（推定）と controller.js（制御）に分けてあり、 どちらも DOM もブラウザ API も触りません。Float64Array と明示的な構造体だけで書いてあるので、 C++ なら std::array<double, 6>、Rust なら [f64; 6] にほぼ1対1で写せます （ホットパスでメモリを確保しない、例外を投げない、状態は明示的に持つ、時刻は引数で受け取る、単位を名前に書く、の約束で書いています）。

制御側の出力は position() / move() / click() / release() / recenter() の5つだけです。 MCU に載せるときは、この5つをモータ制御に置き換えれば controller.js はそのまま動きます （時刻を引数で受け取るので、タイマ割り込みからそのまま呼べます）。

注意・制約

  • 精度は頭の位置に強く依存します。キャリブレーションのときと同じ姿勢を保つのが一番効きます
  • 全画面で使う前提です。ウィンドウ表示だと画面座標とページ座標がズレて狙った場所に行きません
  • キャリブレーション結果は localStorage に保存するので、姿勢を変えなければ次回は CALIBRATE を飛ばせます
  • HUD の LATENCY は「視線サンプルから制御側が動かすまで」の実測値、CAMERA は実際に取れている解像度と fps です。要求した 60fps が来ていないことが多いので、まずここを見てください
  • 視線が途切れると一時停止します。顔を見失ったまま 2.5 秒経つと要再アームになるので、START TRACKING を押し直してください
  • 遅延や誤差で狙った場所に行かないことがあります。視線だけで長文を書くのはまだつらい精度です
  • カメラの映像はブラウザの中でしか使っていません。どこにも送信しません
