gaze-cursor

Webカメラの映像から視線を推定して、カーソルを目で動かす

これは Web 上だけで完結するコンテンツではありません。視線の推定そのものはブラウザの中 （MediaPipe の WASM）で完結しますが、OS のカーソルを動かすにはローカルで動く小さなブリッジが要ります。 ブリッジは others/gaze-cursor/bridge.py で、追加のインストールは不要（Python の標準ライブラリだけ）です。

概要

画面の9点を順に注視してもらって、そのときの目と虹彩の位置から画面座標への回帰を最小二乗で解きます。 あとはキャリブレーション結果に今の目の位置を突っ込んで、出てきた座標にカーソルを寄せていくだけです。

カーソルはブラウザから直接動かせないので、ブリッジが /dev/uinput に仮想マウスを作って 相対移動イベントを書き込みます。カーネルから見ると普通のマウスなので、 Wayland（niri）でも X11 でも同じように動き、root も ydotool も要りません。 ただし相対移動だとカーソルの現在位置が分からないので、ページ側が mousemove で実際の位置を受け取って差分をループで詰めています。ポインタ加速がかかっていても この閉ループが吸収してくれるので、環境ごとのゲイン調整は不要です。

使い方

  1. リポジトリのルートで python3 others/gaze-cursor/bridge.py を実行
  2. 表示された http://127.0.0.1:8765/others/gaze-cursor/ を Chrome で開く
  3. START を押してカメラを許可（全画面になります）
  4. CALIBRATE を押して、出てくる9点を順に目で追う
  5. START TRACKING でカーソルが視線で動きます。注視したままにすると左クリックします

止めるときは Esc（全画面解除で追跡も停止）か、ブリッジ側の Ctrl+C が確実です。

仕組み

要素内容
視線推定 MediaPipe FaceLandmarker（478点）の虹彩ランドマークを、目頭・目尻の線分と上瞼・下瞼の線分に射影して比率化
キャリブレーション 9点それぞれで40フレームの中央値を取り、その特徴量から画面座標へのリッジ回帰を x/y 別に解く
カーソル移動 ブリッジが /dev/uinput に作った仮想マウスへ相対移動を送信。位置は mousemove のフィードバックで収束させる
注視クリック 視線が 900 ms 止まったら左クリック（画面に進捗リングが出ます）
なめらか化 直近3フレームの中央値で単発のスパイクを落としてから 1€ filter に通す。止まっているときは強く平滑化し、速く動くときは遮断周波数を上げて遅れを出さない
計測 HUD に、移動指令からカーソルが実際に動くまでの遅延、カメラの実解像度と fps、顔検出の取りこぼし率を常に出している

注意・制約

  • 精度は頭の位置に強く依存します。キャリブレーションのときと同じ姿勢を保つのが一番効きます
  • 全画面で使う前提です。ウィンドウ表示だと画面座標とページ座標がズレて狙った場所に行きません
  • キャリブレーション結果は localStorage に保存するので、姿勢を変えなければ次回は CALIBRATE を飛ばせます
  • HUD の LATENCY は移動指令からカーソルが動くまでの実測値、CAMERA は実際に取れている解像度と fps です。要求した 60fps が来ていないことが多いので、まずここを見てください
  • 遅延や誤差でカーソルが狙った場所に行かないことがあります。視線だけで長文を書くのはまだつらいです
  • このページを公開サイト上で開いた場合でも、ローカルでブリッジが動いていれば 127.0.0.1:8765 に繋ぎにいきます（動いていなければ START の時点で弾かれます）
  • ブリッジは 127.0.0.1 だけで待ち受けます。外部からは触れません
